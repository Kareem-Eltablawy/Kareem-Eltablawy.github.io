Technical Architecture
Unreal Engine 5
C++ Animation Architecture — FAnimInstanceProxy, Zero AnimGraph VM
Hand-written FAnimInstanceProxy pipeline across all character types — Witch, Butcher, Bee, Dinosaur, GreyStone, GiantGuardian, Damsel, Soldier, Sparrow, and Sarah's MetaHuman face — each owning a typed proxy subclass evaluating directly into FCompactPose on the worker thread. Every bone routed by index; no AnimBP overhead, no AnimGraph VM execution. Three blend modes: Mode A for instant swap, Mode B for crossfade, Mode C for snapshot-from-current-pose via CaptureSnapshot() on all interrupts and transitions — no pose pop regardless of frame rate. Upper and lower body run as fully independent concurrent layers in the same evaluate call. Sarah's face proxy additionally injects blink alpha as named animation curves into FBlendedCurve each frame, consumed downstream by the MetaHuman face post-process ABP through ControlRig and RigLogic.
Zero-Tick Behavioral Systems — Pure Event-Driven, No Polling
Not one bCanEverTick enabled on any brain component across the full roster. Every behavioral output fires from a named C++ function call triggered by a scheduled FTimerHandle, an overlap callback, or an animation-completion event. Five enemy archetypes — a 14-state boss with a one-way revenge latch and live team HP injection, a 15-phase melee fighter with four personality archetypes, a flying minion with 13 FTimerHandle slots and orbital flight via TeleportPhysics, and two grounded minions with kinematic lunge derived from kinematic formulas. Three companion types share a unified follow FSM with world-space HoldGround anchors and a single round-robin command cursor. No coordinator. No shared authority. No polling.
Citizen NPC Systems — Parallel State Machines, Per-Bone Eye Tracking
HumanElf citizens run two parallel independent state machines simultaneously: an interaction machine covering warn flow with indexed four-asset bundles (face animation, audio, body animation, write-body animation), and a HyperAwareness machine driving report and tax paths — each with super-matched index pairing so face animation and audio are always from the same emotionally coherent set across every phase boundary. Head rotation clamped per personality and smoothed via FQuat::Slerp(); eyes tracked per-bone with exponential-decay smoothing (1 − e^(−speed·Δt)) applied automatically the moment all holders release. Groom, body, face, and clothes LOD managed via scalability delegate — no per-frame polling.
Actor Pooling & Spatial Activation — No Runtime Spawning
No actor spawns or destroys at runtime. MonsterArea assigns spawn points via Fisher-Yates slot shuffling at activation; every enemy teleports to its point, activates, then resets and goes dormant on exit. Arrow projectiles across Sparrow, Bee, and GreyStone run off pre-built 20-slot UStaticMeshComponent pools constructed in the character constructor with SetUsingAbsoluteLocation(true) — no AActor spawn, no UProjectileMovementComponent, no physics component. Arrow flight runs at 30 Hz via repeating FTimerHandle with dual hit detection per tick: weak-pointer list scan and live sphere overlap query. Facial solves gated by proximity: nearby MetaHumans receive full face proxy evaluation; distant NPCs fall back to body-only locomotion.
Data Systems & GC Contract — Single Source of Truth, Field-Level Enforcement
Every tunable parameter — blend speeds, damage tables, anim sequence sets, detection radii, attack probability distributions, dialogue pools, patrol waypoints — lives in a typed UPrimaryDataAsset hierarchy loaded once via LoadSynchronous() at BeginPlay. Runtime reads flat cached copies — plain floats, raw UAnimSequence*, uint8 enums — with no BP node evaluation and no soft reference resolves on any hot path. Every owned UObject* declared UPROPERTY() TObjectPtr<>; every cross-actor reference uses TWeakObjectPtr<> with explicit IsValid() guards before every dereference. No heap temporaries. No TArray allocations in hot paths. Worker thread sees a flat, allocation-free evaluation path every frame.

Data-Driven Scriptable Object Architecture — Config Fully Decoupled
Full Scriptable Object pipelines serve as the single source of truth across all projects, with SO values injectable at runtime via JSON feeds from ASP.NET backends and external REST APIs — server data flows directly into game state without touching code or triggering rebuilds. Cross-game progression, save state, and live configuration changes all resolve through the same pipeline. The contract is explicit: Server → SO → game, with no intermediate code changes and no runtime dependencies on the data source.
Event-Driven Architecture — Near-Zero Update Loop
The Update loop is reserved strictly for animation, physics, and player input; every other system — state changes, NPC triggers, UI updates, progression tracking — responds to C# events and UnityEvent signals. No continuous polling, no redundant per-frame checks. Systems are wired at bind time so event emission is the only path to state change, making per-frame cost proportional to actual activity rather than scene population.
