⚙ Technical Architecture
⚔ Unreal Engine 5 — Native C++ Systems
▸Animation Architecture — FAnimInstanceProxy, Zero AnimGraph VM
Hand-written FAnimInstanceProxy pipeline across ten character types — Witch, Butcher, Bee, Dinosaur, GreyStone, GiantGuardian, Damsel, Soldier, Sparrow, and Sarah's MetaHuman face — each owning a typed proxy subclass evaluating directly into FCompactPose on the worker thread. Every bone routed by index; no AnimBP overhead, no AnimGraph VM execution. Three blend modes: Mode A for instant swap, Mode B for crossfade, Mode C for snapshot-from-current-pose via CaptureSnapshot() on all interrupts and death — no pose pop regardless of frame. Upper and lower body run as fully independent concurrent layers in the same evaluate call. Sarah's face proxy injects blink alpha as named animation curves into FBlendedCurve, consumed by the MetaHuman post-process ABP through ControlRig and RigLogic.
▸AVX2 / AVX-512 Bone Blend — SIMD, Cache-Line & Floor Proofs
Replaced all per-bone blending with a hand-written AVX2 4-wide / AVX-512 8-wide pipeline. CPUID runtime dispatch selects the wide path at startup; Intel CPU downclocking detection guards against frequency-scaled degradation. FTransform layout locked by static_assert byte-offset guards. Remez degree-3 minimax polynomial replaces FMath::Atan2: 12 instructions vs 25–40, verified 0.2 µs/frame savings at 50 actors. Hot structs fit one cache line with alignas(64) and verified byte offsets. SoA Sentinel Arrays with FLT_MAX sentinels for branchless early-exit. Every optimization gap documents instruction count × cycle math × µs/frame at actor count — permanently closed when nothing can be removed.
▸Packed uint32 MegaState — Register-Level AI
Companion AI (GreyStone) built as packed uint32 MegaState with two alignas(64) hot structs — all FSM fields extractable in exactly two x64 instructions via SHR/AND register extraction. State transitions are pure C file-scope functions: no virtual dispatch, no heap allocation, no dynamic branching. Zero Blueprint VM on any state path. Every decision reads from flat cached data with no soft reference resolves.
▸Zero-Tick Behavioral Systems — Pure Event-Driven
Not one bCanEverTick enabled on any brain component. All behavioral output fires from named C++ functions triggered by FTimerHandle one-shots, overlap callbacks, or animation-completion events. Five archetypes: 14-state boss with revenge latch and live team HP injection; 15-phase melee fighter with four personality archetypes and quadratic Bézier arc approach interrupted mid-arc; flying minion with 13 timer slots and orbital flight via TeleportPhysics; two grounded minions with kinematic lunge. Three companions on a unified follow FSM with world-space HoldGround anchors, single round-robin command cursor. No coordinator. No shared authority. No polling.
▸Citizen NPC Systems — Parallel FSMs & Per-Bone Eye Tracking
HumanElf citizens run two parallel independent state machines: an interaction machine covering warn flow with indexed four-asset bundles (face animation, audio, body animation, write-body animation), and a HyperAwareness machine driving report and tax paths — super-matched index pairing so face and audio are always emotionally coherent across every phase boundary. Head rotation clamped per personality and smoothed via FQuat::Slerp(); eyes tracked per-bone with exponential-decay smoothing (1 − e^(−speed·Δt)) applied the moment all holders release. Groom, body, face, and clothes LOD via scalability delegate — no per-frame polling.
▸Actor Pooling & Spatial Activation — Zero Runtime Spawning
No actor spawns or destroys at runtime. MonsterArea assigns spawn points via Fisher-Yates slot shuffling; enemies teleport to their point, activate, then reset and go dormant on exit. Arrow projectiles run off pre-built 20-slot UStaticMeshComponent pools constructed in the character constructor with SetUsingAbsoluteLocation(true) — no AActor spawn, no UProjectileMovementComponent, no physics component. Arrow flight at 30 Hz via repeating FTimerHandle with dual hit detection per tick: weak-pointer list scan and live sphere overlap query. Facial solves gated by proximity.
▸Data Systems & GC Contract — Field-Level Enforcement
Every tunable parameter — blend speeds, damage tables, anim sequence sets, detection radii, attack probability distributions, patrol waypoints — lives in a typed UPrimaryDataAsset hierarchy loaded once via LoadSynchronous() at BeginPlay. Runtime reads flat cached copies — plain floats, raw UAnimSequence*, uint8 enums — no BP node evaluation, no soft reference resolves. Every owned UObject* declared UPROPERTY() TObjectPtr<>; every cross-actor reference uses TWeakObjectPtr<> with explicit IsValid() guards before every dereference. Worker thread sees a flat, allocation-free evaluation path every frame.
◈ Unity — C# Systems Architecture
▸Hand-Written AI Systems — BTs, FSMs, Utility AI from Scratch
All AI decision logic designed and implemented from scratch in C# — Behavior Trees, Finite State Machines, and Utility AI systems fully owned at the code level. No engine defaults, no third-party frameworks. Applied across strategy, simulation, and open-world environments sustaining large NPC counts on mobile without frame degradation. ▸Data-Driven Scriptable Object Architecture
Full Scriptable Object pipelines serve as the single source of truth across all projects. SO values injectable at runtime via JSON feeds from ASP.NET backends and external REST APIs — server data flows directly into game state without touching code or triggering rebuilds. Cross-game progression, save state, and live configuration all resolve through the same pipeline. Contract is explicit: Server → SO → game. No intermediate code changes, no runtime dependencies on the data source.
▸Event-Driven Architecture — Near-Zero Update Loop
Update loop reserved strictly for animation, physics, and player input — every other system responds to C# events and UnityEvent signals. No continuous polling, no redundant per-frame checks. Systems are wired at bind time so event emission is the only path to state change, making per-frame cost proportional to actual activity rather than scene population. An architectural constraint, not a guideline.
▸Performance — DOTS, World Streaming, LOD Chains & Pooling
World streaming and object pooling for large open environments combined with AI LOD and pooled components to sustain stable frame rates and reduce GC pressure on mobile. 3D models optimised directly in Unity — polycounts, LOD chains, material simplification — to hit mobile performance budgets without post-export fixes. ECS, Job System, and Burst Compiler applied for CPU-bound simulation workloads where single-threaded C# evaluation could not meet frame time targets.
