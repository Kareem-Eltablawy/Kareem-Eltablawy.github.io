Technical Architecture
Unreal Engine 5 — Native C++ Systems
Day/night cycle event-driven, no Tick
  • Run the sun, sky, fog, moon, post-process and tagged lamps from timers and baked per-minute data instead of Tick.
  • Broadcast hour, day and night events through multicast delegates so other systems subscribe instead of polling.
  • Hand lighting over at sunrise and sunset in two frames: switch the leaving group off, verify it, then switch the arriving group on.
  • Store the cycle in a Data Asset with an editor Bake step that validates itself, logs problems and rebuilds when stale.
  • Auto-discover lights and volumes by tag and keep the clock non-spatially-loaded for World Partition.
NPC daily routines
  • Drive NPC schedules from the world clock's hour event: compare a baked weekly timetable to the current behavior and run a routine only when they differ.
  • Run routines as step lists on one-shot timers, with mid-day resume on level load and navmesh retry/skip fallbacks.
  • Keep NPC state packed into bit fields in a cache-line-aligned hot struct, and dispatch steps through a jump table.
Animation
  • Wrote a custom FAnimInstanceProxy that samples sequences directly on the worker thread, with no per-frame game-thread animation update.
  • Blend between states with a frozen snapshot of the outgoing pose, so interrupts never pop and a second sample is taken only during the blend window.
  • Bake the animation slot table from Data Assets on first load, rejecting invalid or additive sequences and logging missing assets.
Companions
  • Companion NPCs with no actor Tick, AI-driven movement through direct velocity writes, and a pooled-style activate/deactivate lifecycle that clears timers on despawn.
  • Cache raw engine pointers from GC-owned UPROPERTYs after every anim rebuild, and register companions with the player character for a player-led team with commands and roster limits.
AI & combat
  • Enemy, companion and NPC AI written entirely in C++, with attacks, dodging, defending and hit reactions.
Data-driven design
  • Designers tune schedules, animations, timings and lighting in Data Assets without changing code.
Performance
  • Event-driven logic, distance-based AI and animation LOD, and compact cache-line-aligned data for hot paths.
Unity — C# Systems Architecture
AI — BTs, FSMs & Utility AI
All decision logic built from scratch in C# — no engine defaults, no third-party frameworks. Behavior Trees, Finite State Machines and Utility AI systems fully owned at the code level, applied across strategy, simulation and open-world environments sustaining large NPC counts on mobile without frame degradation. State transitions are discrete and auditable — no implicit graph traversal, no hidden per-frame evaluation.
Data-Driven Scriptable Objects
Full ScriptableObject pipelines as the single source of truth across all projects — config fully decoupled from logic. SO values are injectable at runtime via JSON feeds from ASP.NET backends and external REST APIs, so server data flows directly into game state without touching code or triggering rebuilds. Cross-game progression, save state and live configuration changes all resolve through the same pipeline. The contract is explicit: Server → SO → game.
Event-Driven, Near-Zero Update
The Update loop is reserved strictly for animation, physics and player input, where frame-continuous evaluation is unavoidable. Every other system — state changes, NPC triggers, UI updates, progression tracking — responds to C# events and UnityEvent signals. No continuous polling, no redundant per-frame checks: systems are wired at bind time so event emission is the only path to state change.
Performance — DOTS & World Streaming
World streaming and object pooling for large open environments, combined with AI LOD techniques and pooled components, sustain stable frame rates on mobile targets. 3D model optimization happens directly in Unity — polycounts, LOD chains, simplified materials — without relying on post-export fixes. ECS, Job System and Burst Compiler are applied for CPU-bound simulation workloads where single-threaded C# evaluation could not meet frame time targets.
