Technical Architecture
Unreal Engine 5
Custom FAnimInstanceProxy Pipeline — Dual Proxies, Zero AnimGraph VM
Two hand-written proxies evaluate directly into FCompactPose on the worker thread with no AnimBP overhead and no AnimGraph VM execution — every bone routed by index. The body proxy runs a four-priority Evaluate() chain and snapshots each frame into a TArray<FTransform> via CaptureSnapshot(); the face proxy independently handles blink alpha injection, gaze rotation, FAnimNode_ControlRig head IK, and FAnimNode_RigLogic blend shapes with live alpha blending. NativeUpdateAnimation() on the game thread fills a flat write surface — a struct of floats and indices — which the proxy reads in Evaluate(). No state crosses the thread boundary; no decision logic exists in animation code. The separation is enforced by architecture, not convention.
Zero-Tick Behavioral Systems — Pure Event-Driven, Twelve FTimerHandles
Not one bCanEverTick enabled anywhere in the system. Every behavioral output — greeting, discomfort escalation, anger, flee-interception — fires from a scheduled C++ callback. The soldier brain alone manages twelve FTimerHandles; each soldier maintains a dedicated overlap sphere that re-evaluates flee-state every four seconds, intercepts regardless of player path, deducts 1% coin balance on contact, and escalates greeting locks (16-minute first offense, permanent second). Citizens operate as fully independent decision-makers — each tracks player behavior through its own event-driven state machine and decides autonomously to greet, escalate, walk away, or report. No coordinator. No shared authority.
Full Emotional Escalation & RDR2-Depth Look-At — No Manager Class, No Cuts
Citizens transition from neutral through discomfort to anger and confront via a ramping alpha sequence driven entirely by the face proxy, with RigLogic correcting blend shapes every frame throughout. Every transition originates from the actual current pose via CaptureSnapshot(), eliminating pops — no state jumps, no pose cuts, only continuously weighted blends. Head rotation clamped to PI/3.9f per personality and blended via FQuat::Slerp(); eyes tracked via smoothed vectors on FACIAL_L/R_Eye bones, clamped to EyeGazeClampAngleDegrees. HeadLookAtAlpha and FriendlyEyeGazeAlpha held independently by any subsystem and decay automatically via FInterpTo() the moment all holders release. No manager class. No polling.
Enemy AI — Flat C++ State Machine, Four States, Fourteen Attack Sub-Phases
All decision logic lives in one flat C++ file with no blackboard and no decorator chains. Jump attacks fire from two independent triggers — a distance roll at engagement start and a looping timer during extended chases — using a manual parabolic arc via SetActorLocation() with animation scrubbed by distance fraction rather than time, so every jump length looks correct regardless of distance. Attack variants scale from 0% combo chance at slot 1 to 60% at slot 4, rising with consecutive hits; one team sighting fans out to the full group instantly. Below half HP the enemy breaks to a waypoint, plays a full heal animation across independent upper and lower body layers, restores HP on completion, then re-engages. Leader and member roles react to death differently; the last survivor carries stacked speed bonuses.
Actor Pooling & NPC Architecture — No Runtime Spawning, One Subclass Per Type
No actor spawns or destroys at runtime. Every enemy and NPC sits tick-disabled and hidden until the player enters the activation volume, teleports to a shuffled spawn point, activates, then resets and goes dormant on exit. Facial solves gated by proximity sphere: nearby MetaHumans receive full face proxy evaluation; distant NPCs fall back to body-only locomotion. NPC behavior built on a common base component — proximity reactions, greeting chains, comfort zone tracking, discomfort escalation, walk-away logic — with a UENUM-tagged category driving virtual dispatch per type. Each new NPC variant costs one .h, one .cpp, and one Data Asset fill. Zero duplication, zero runtime dispatch overhead.
Data Systems & GC Contract — Single Source of Truth, Field-Level Enforcement
Every tunable parameter — blend speeds, comfort radius, anger thresholds, hospitality tiers, greeting pools, combat profiles, voice line arrays, AnimSequence sets — lives in a typed UPrimaryDataAsset following a Base → Soldier → Damsel hierarchy. Loaded once with LoadSynchronous() at BeginPlay; runtime reads flat cached copies — plain floats, raw UAnimSequence*, uint8 enums — with no BP node evaluation and no soft reference resolves. Every UObject* declared UPROPERTY() TObjectPtr<>; cross-actor references use TWeakObjectPtr<> with explicit .IsValid() guards before every dereference. All math scalar and named — FMath::FInterpTo(), FQuat::Slerp(), FTransform::Blend() called directly with results in named locals. No heap temporaries. No TArray allocations in hot paths.

Data-Driven Scriptable Object Architecture — Single Source of Truth, Config Fully Decoupled
Full Scriptable Object pipelines serve as the single source of truth across all projects, with SO values injectable at runtime via JSON feeds from ASP.NET backends and external REST APIs — server data flows directly into game state without touching code or triggering rebuilds. Cross-game progression, save state, and live configuration changes all resolve through the same pipeline; the data layer and logic layer share no coupling, so tuning, balancing, and backend-driven updates require zero code intervention. The contract is explicit: Server → SO → game, with no intermediate code path changes and no runtime dependencies on the data source.
Event-Driven Architecture — Near-Zero Update Loop
The Update loop is reserved strictly for animation, physics, and player input; every other system — state changes, NPC triggers, UI updates, progression tracking — responds to C# events and UnityEvent signals. No continuous polling, no redundant per-frame checks. This is an architectural constraint, not a guideline: systems are wired at bind time so event emission is the only path to state change, making per-frame cost proportional to actual activity rather than scene population.
